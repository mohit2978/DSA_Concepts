


## Q1. Meeting Rooms (LeetCode 252)

**Problem:** Given an array of meeting time intervals `intervals` where `intervals[i] = [start_i, end_i]`, determine if a person could attend all meetings.

**Example 1:**
```
Input: intervals = [[0,30],[5,10],[15,20]]
Output: false
```

**Example 2:**
```
Input: intervals = [[7,10],[2,4]]
Output: true
```

**Constraints:**
- `0 <= intervals.length <= 10^4`
- `intervals[i].length == 2`
- `0 <= start_i < end_i <= 10^6`

**Key idea:** reuse the same sort-by-start `Pair` class from Q1. A person can attend every meeting only if **no two meetings overlap at all** — so after sorting, walk through consecutively and the moment one meeting starts before the previous one has ended, return `false` immediately.

**Java:**
```java
public boolean canAttendMeetings(int[][] intervals) {
    if (intervals.length == 0) return true;
    Pair[] arr = new Pair[intervals.length];
    for (int i = 0; i < intervals.length; i++) {
        arr[i] = new Pair(intervals[i][0], intervals[i][1]);
    }
    Arrays.sort(arr);
    Stack<Pair> stk = new Stack<>();
    stk.push(arr[0]);
    for (int i = 1; i < arr.length; i++) {
        Pair prev = stk.peek();
        if (arr[i].st >= prev.ed) stk.push(arr[i]);
        else return false;
    }
    return true;
}
```

**C++** (added since only Java existed):
```cpp
bool canAttendMeetings(vector<vector<int>>& intervals) {
    if (intervals.empty()) return true;
    vector<Pair> arr;
    for (auto &iv : intervals) arr.push_back(Pair(iv[0], iv[1]));
    sort(arr.begin(), arr.end());
    stack<Pair> stk;
    stk.push(arr[0]);
    for (int i = 1; i < (int)arr.size(); i++) {
        Pair prev = stk.top();
        if (arr[i].st >= prev.ed) stk.push(arr[i]);
        else return false;
    }
    return true;
}
```

A quick self-made check: `[1,3]` and `[13,15]` → `true` (no overlap at all, so attending both is possible), matching the logic above. The first attempt at this on LeetCode actually hit a Runtime Error and then a Wrong Answer before landing on the accepted version above — the bug was returning the *opposite* boolean of what was intended, fixed by making sure only an actual overlap (`arr[i].st < prev.ed`) triggers `false`.

**Time Complexity: `O(N log N)`** — sorting dominates; the scan afterward is `O(N)`.
**Space Complexity: `O(N)`** — for the `Pair[]` array built from the input.

## Q3. Meeting Rooms II (LeetCode 253)

**Problem:** Given an array of meeting time intervals `intervals` where `intervals[i] = [start_i, end_i]`, return the minimum number of conference rooms required.

**Example 1:**
```
Input: intervals = [[0,30],[5,10],[15,20]]
Output: 2
```

**Example 2:**
```
Input: intervals = [[7,10],[2,4]]
Output: 1
```

**Key idea, and why it's harder than Q2:** this isn't just "do any two meetings overlap" — it's "what's the **maximum number of meetings happening at the same time**, at any point in time?" In Example 1, `[0,30]` needs a room for its whole duration; `[5,10]` needs a *second* room since `[0,30]`'s room is still occupied; but once `[5,10]` ends, that room frees up, so `[15,20]` can reuse it instead of needing a third room — hence the answer is `2`, not `3`.

 **approach — chronological ordering (two pointers over sorted starts/ends):**

Split every interval into its start and end, sort the two lists **independently**. Walk through the start times in order; whenever the next meeting's start is earlier than the earliest still-unprocessed end, a *new* room is needed (`rooms++`); otherwise, some room has already freed up by then, so reuse it (`rooms--`, then account for the new meeting via the next comparison). Track the running maximum of `rooms` as the answer. This sidesteps the stack's LIFO limitation entirely, since `ends[]` is always consulted in true chronological order regardless of push order.

**Dry run** on Example 1 — `starts=[0,5,15]`, `ends=[10,20,30]`:
- `starts[0]=0 < ends[0]=10` → `rooms=1` (max 1), advance start pointer.
- `starts[1]=5 < ends[0]=10` → `rooms=2` (max 2), advance start pointer.
- `starts[2]=15 < ends[0]=10`? No → `rooms=1`, advance end pointer.
- All starts consumed → **answer = 2**, matching the expected output.

(Verified the same way against both of the wrong-answer cases above: `[[9,10],[4,9],[4,17]]` → `2`, and `[[0,30],[2,5],[5,10],[5,7],[5,8],[15,20]]` → `4`, correctly resolving both bugs the stack approach ran into.)

**Java:**
```java
public int minMeetingRooms(int[][] intervals) {
    int n = intervals.length;
    if (n == 0) return 0;
    int[] starts = new int[n];
    int[] ends = new int[n];
    for (int i = 0; i < n; i++) {
        starts[i] = intervals[i][0];
        ends[i] = intervals[i][1];
    }
    Arrays.sort(starts);
    Arrays.sort(ends);
    int rooms = 0, maxRooms = 0;
    int s = 0, e = 0;
    while (s < n) {
        if (starts[s] < ends[e]) {
            rooms++;
            s++;
        } else {
            rooms--;
            e++;
        }
        maxRooms = Math.max(maxRooms, rooms);
    }
    return maxRooms;
}
```

**C++:**
```cpp
int minMeetingRooms(vector<vector<int>>& intervals) {
    int n = intervals.size();
    if (n == 0) return 0;
    vector<int> starts(n), ends(n);
    for (int i = 0; i < n; i++) {
        starts[i] = intervals[i][0];
        ends[i] = intervals[i][1];
    }
    sort(starts.begin(), starts.end());
    sort(ends.begin(), ends.end());
    int rooms = 0, maxRooms = 0;
    int s = 0, e = 0;
    while (s < n) {
        if (starts[s] < ends[e]) {
            rooms++;
            s++;
        } else {
            rooms--;
            e++;
        }
        maxRooms = max(maxRooms, rooms);
    }
    return maxRooms;
}
```

**Time Complexity: `O(N log N)`** — two independent sorts of size `N`; the two-pointer sweep afterward is `O(N)`.
**Space Complexity: `O(N)`** — for the separate `starts[]` and `ends[]` arrays.

## Q4. The Celebrity Problem / Find the Celebrity (GFG · LeetCode 277)

**Definition:** a **celebrity** is a person who is known by everyone else at the party, but knows none of them. Given an `n x n` matrix `M` where `M[i][j] == 1` means person `i` knows person `j` (and `0` otherwise), find the celebrity's index, or determine that none exists.

**Equivalent LeetCode framing (277 — Find the Celebrity):**

Suppose you are at a party with `n` people labeled from `0` to `n - 1` and among them, there may exist one celebrity. The definition of a celebrity is that all the other `n - 1` people know the celebrity, but the celebrity does not know any of them.

Now you want to find out who the celebrity is or verify that there is not one. The only thing you are allowed to do is ask questions like: "Hi, A. Do you know B?" to get information about whether A knows B. You need to find out the celebrity (or verify there is not one) by asking as few questions as possible (in the asymptotic sense).

You are given a helper function `bool knows(a, b)` that tells you whether A knows B. Implement a function `int findCelebrity(n)`. There will be exactly one celebrity if they are at the party.

Return the celebrity's label if there is a celebrity at the party. If there is no celebrity, return `-1`.

**Example 1:**
```
Input: graph = [[1,1,0],[0,1,0],[1,1,1]]
Output: 1
Explanation: There are three persons labeled with 0, 1 and 2. graph[i][j] = 1 means
person i knows person j, otherwise graph[i][j] = 0 means person i does not know
person j. The celebrity is the person labeled as 1 because both 0 and 2 know him
but 1 does not know anybody.
```

**Example 2:**
```
Input: graph = [[1,0,1],[1,1,0],[0,1,1]]
Output: -1
Explanation: There is no celebrity.
```

**Constraints:**
- `n == graph.length == graph[i].length`
- `2 <= n <= 100`
- `graph[i][j]` is `0` or `1`
- `graph[i][i] == 1`

**Approach 1: Two pointers**

Start `i=0` at one end and `j=n-1` at the other. At each step, whoever *knows* the other person can't possibly be the celebrity, so move that pointer inward: if `M[i][j]==0` (`i` doesn't know `j`), move `j--`; otherwise `i` knows `j`, so `i` is disqualified, move `i++`. Once `i==j`, that single remaining index is the *only possible* candidate — but it still needs verifying, since elimination alone can still leave some arbitrary survivor when no true celebrity exists. Verification: the candidate fails if it knows anyone else, or if anyone else doesn't know it.

**Dry run** on a custom `5x5` matrix (people `0`-`4`):
```
     0  1  2  3  4
  0  0  1  0  1  0
  1  1  0  1  0  0
  2  1  1  0  1  1
  3  0  0  0  0  0
  4  1  1  1  0  0
```
- `i=0, j=4`: `M[0][4]=0` → `0` doesn't know `4`, so `j--` → `j=3`.
- `i=0, j=3`: `M[0][3]=1` → `0` knows `3`, so `0` is disqualified, `i++` → `i=1`.
- `i=1, j=3`: `M[1][3]=0` → `1` doesn't know `3`, so `j--` → `j=2`.
- `i=1, j=2`: `M[1][2]=1` → `1` knows `2`, so `1` is disqualified, `i++` → `i=2`.
- `i==j==2` → loop stops. Candidate = `2`.
- **Verify candidate `2`:** check `k=0`: `M[2][0]=1` → `2` knows `0` → fails the "knows no one" requirement immediately.
- **Result: `-1`** — this particular practice matrix has no celebrity.

**Why the verification step is mandatory:** the elimination phase only *guarantees* finding the true celebrity if one exists — it doesn't guarantee the survivor is a valid celebrity when none exists. (Running the *stack-based* elimination further below on this exact same matrix, in a different pairing order, actually survives on a *different* index, `0` — and it also correctly fails verification, for the same reason: `M[0][1]=1`, so `0` knows `1`. Both approaches agree there's no celebrity, even though they land on different "candidates" along the way — that's expected, not a contradiction.)


```cpp
class Solution
{
public:
    int celebrity(vector<vector<int>> &M){
        int n=M.size();
        int i=0;
        int j=n-1;
        while(i<j){
            if(M[i][j]==0) j--;
            else i++;
        }
        for(int k=0;k<n;k++){
            if(k!=i && (M[i][k]==1 || M[k][i]==0)) return -1;
        }
        return i;
    }
};

```



**Java** (same matrix-based logic as the C++ above, added since only C++ existed):

**Approach 2: the same two pointers, but against the LeetCode `knows(a, b)` API directly (no matrix needed)**

When the input isn't a matrix but the `knows(a, b)` helper described in LC277, the identical two-pointer logic applies — just replace `M[i][j]` with a `knows(i, j)` call. This is actually a strict improvement in space: no matrix has to be stored at all, since every comparison is answered on demand.

**Java** (submitted without errors, 13ms — faster than 99.83% of Java submissions):
```java
/* The knows API is defined in the parent class Relation.
      boolean knows(int a, int b); */

public class Solution extends Relation {
    public int findCelebrity(int n) {
        int st = 0;
        int ed = n - 1;
        while (st < ed) {
            if (knows(st, ed) == true) st++;
            else ed--;
        }
        for (int i = 0; i < n; i++) {
            if ((i != st) && (knows(st, i) == true || knows(i, st) == false))
                return -1;
        }
        return st;
    }
}
```

**C++** (added since only Java existed):
```cpp
/* The knows API is defined for you.
      bool knows(int a, int b); */

class Solution {
public:
    int findCelebrity(int n) {
        int st = 0;
        int ed = n - 1;
        while (st < ed) {
            if (knows(st, ed)) st++;
            else ed--;
        }
        for (int i = 0; i < n; i++) {
            if (i != st && (knows(st, i) || !knows(i, st))) return -1;
        }
        return st;
    }
};
```

(The notes also mention an alternate `void`/print-based signature — `findCelebrity(int[][] arr)` printing the index or `"none"` instead of returning it — matching a specific practice platform's expected format; the logic is identical to the matrix-based version above, just wrapped differently.)

**Time Complexity (both matrix-based and API-based two-pointer versions): `O(N)`** — the elimination phase moves `i` or `j` inward on every step, so it finishes in at most `N-1` steps total; the verification loop afterward is a single `O(N)` pass.
**Space Complexity: `O(1)`** extra — only the two pointers, no auxiliary structure (beyond the input matrix itself, if one is given).

## Q5. Design Two Stacks in a Single Array (GFG)

**Problem:** implement two stacks that share a single fixed-size array, so that neither stack overflows until the array is genuinely full (i.e. avoid the wasteful approach of splitting the array in half up front, which overflows one stack early even while the other half sits empty).

**Key idea:** grow the first stack from the **left end** of the array upward (`tos1` starts at `-1`, incremented on push), and grow the second stack from the **right end** downward (`tos2` starts at `data.length`, decremented on push). The two stacks only collide — and the array is only actually full — when they meet in the middle: `tos1 + 1 == tos2`.




 ```java
public class TwoStack {
    int[] data;
    int tos1;
    int tos2;
    int sz1;
    int sz2;

    public TwoStack(int cap) {
        data = new int[cap];
        tos1 = -1;
        tos2 = cap;
        sz1 = 0;
        sz2 = 0;
    }

    int size1() {
        return sz1;
    }

    int size2() {
        return sz2;
    }

    void push1(int val) {
        if (tos1 + 1 == tos2) {
            System.out.println("Stack overflow");
            return;
        }
        tos1++;
        data[tos1] = val;
        sz1++;
    }

    void push2(int val) {
        if (tos1 + 1 == tos2) {
            System.out.println("Stack overflow");
            return;
        }
        tos2--;
        data[tos2] = val;
        sz2++;
    }
```

**Dry run** — array capacity `5`, after `push1(10)`, `push1(30)`, `push2(20)`, `push2(40)`, `push2(50)`:
```
index:  0    1    2    3    4
data:  [10,  30,  50,  40,  20]
             tos1↑    tos2↑
```
`tos1=1` (2 elements pushed on stack 1: `10, 30`), `tos2=2` (3 elements pushed on stack 2, in order `20, 40, 50`, so `50` is on top). At this point `tos1 + 1 = 2 = tos2` — the array is completely full, so **any further `push1` or `push2` correctly reports `"Stack overflow"`** without touching the array.

**Underflow condition** for each stack (checked the same way, mirrored around each stack's own starting position): `tos1 == -1` means stack 1 is empty, and `tos2 == data.length` means stack 2 is empty.




```java
    int pop1() {
        if (tos1 == -1) {
            System.out.println("Stack underflow");
            return -1;
        }
        int val = data[tos1];
        data[tos1] = 0;
        tos1--;
        sz1--;
        return val;
    }

    int pop2() {
        if (tos2 == data.length) {
            System.out.println("Stack underflow");
            return -1;
        }
        int val = data[tos2];
        data[tos2] = 0;
        tos2++;
        sz2--;
        return val;
    }

    int top1() {
        if (tos1 == -1) {
            System.out.println("Stack underflow");
            return -1;
        }
        return data[tos1];
    }

    int top2() {
        if (tos2 == data.length) {
            System.out.println("Stack underflow");
            return -1;
        }
        return data[tos2];
    }
}
```

**A space note:** the separate `sz1`/`sz2` counters aren't strictly necessary — `size1()` could instead just return `tos1 + 1`, and `size2()` could return `data.length - tos2`, computed directly from the pointers instead of tracked separately (with the same underflow checks reused).

**C++** (added since only Java existed):
```cpp
class TwoStack {
public:
    vector<int> data;
    int tos1, tos2;
    int sz1, sz2;

    TwoStack(int cap) {
        data.assign(cap, 0);
        tos1 = -1;
        tos2 = cap;
        sz1 = 0;
        sz2 = 0;
    }

    int size1() { return sz1; }
    int size2() { return sz2; }

    void push1(int val) {
        if (tos1 + 1 == tos2) {
            cout << "Stack overflow" << endl;
            return;
        }
        tos1++;
        data[tos1] = val;
        sz1++;
    }

    void push2(int val) {
        if (tos1 + 1 == tos2) {
            cout << "Stack overflow" << endl;
            return;
        }
        tos2--;
        data[tos2] = val;
        sz2++;
    }

    int pop1() {
        if (tos1 == -1) {
            cout << "Stack underflow" << endl;
            return -1;
        }
        int val = data[tos1];
        data[tos1] = 0;
        tos1--;
        sz1--;
        return val;
    }

    int pop2() {
        if (tos2 == (int)data.size()) {
            cout << "Stack underflow" << endl;
            return -1;
        }
        int val = data[tos2];
        data[tos2] = 0;
        tos2++;
        sz2--;
        return val;
    }

    int top1() {
        if (tos1 == -1) {
            cout << "Stack underflow" << endl;
            return -1;
        }
        return data[tos1];
    }

    int top2() {
        if (tos2 == (int)data.size()) {
            cout << "Stack underflow" << endl;
            return -1;
        }
        return data[tos2];
    }
};
```

**Time Complexity: `O(1)` per operation** — `push1`, `push2`, `pop1`, `pop2`, `top1`, `top2` all do a fixed, constant amount of work.
**Space Complexity: `O(N)`** for the shared `data` array (`N` = capacity) — using one array of size `N` for both stacks instead of two separate arrays uses the same total space, but lets either stack grow arbitrarily large as long as the other stays small, instead of both being capped at a fixed half.
